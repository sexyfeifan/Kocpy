# Kocpy 0.1.11

0.1.11 修复外部清单缺失文件在“健康副本目录已重组”时无法补回的问题，并将修复流程升级为先完整暂存、再统一提交的事务式处理。此版本仍未使用 Apple Developer ID 签名与公证。

## 健康副本目录映射

- 修复时可以选择原素材卡根目录、与清单对应的素材子目录，或包含该素材目录的上级目录。
- Kocpy 会根据 MHL/SHA 清单的相对路径寻找完整映射；只有映射唯一时才允许继续。
- 若找不到完整映射，或不同目录同时都能完整匹配，软件会要求选择更精确的目录，不会自行猜测。
- 映射结果会显示为“健康副本目录 → 清单目录”，并写入任务审计日志。
- 目标素材卷与健康副本不能是同一目录，也不能互为上下级，避免把待修复卷误当作健康来源。

## 安全写入与回滚

- 写入前检查全部缺失文件的存在性、大小、清单哈希以及目标卷可用空间。
- 所有文件先写入目标卷上的隐藏暂存目录，并对暂存结果再次计算清单哈希。
- 通过后以不覆盖已有文件的方式提交，防止并发操作或路径变化覆盖现有素材。
- 任一步失败都会删除本次已提交的新文件并清理暂存目录，不留下半套修复结果。
- 提交完成后仍会对整个素材卷执行一次外部清单复校验；只有全部通过才恢复绿色状态。
- 界面错误提示会移除 Electron 远程调用包装，只显示可操作的业务原因。

## 使用说明界面

- 软件内“使用说明”不再默认展开第一个模块。
- 所有模块初始保持折叠，只有用户点击标题后才显示步骤和注意事项，使页面初始状态更紧凑。

## 真实项目排查结论

“纸扎人阿岳”项目的 `20260826/A7CR/Untitled_202608262327` 清单记录 376 项，当前接管目录实际有 262 项，缺少的 114 项位于清单路径 `DCIM/100MSDCF`。用户提供的原版素材位于重组目录 `111/100MSDCF`；114 个文件的名称、大小和 xxHash32 均与原 MHL 完全一致。旧版本失败是因为强制从所选目录根部拼接完整 MHL 路径，并非素材不完整，也不是手动创建项目导致的数据偏差。

## 验证

- 新增重组目录映射测试：`111/100MSDCF` 可正确映射到清单中的 `DCIM/100MSDCF`。
- 新增歧义拒绝测试：两组目录同时完整匹配时，在写入任何文件前停止。
- 保留严格校验测试：大小或哈希不符时目标目录不发生变化。
- TypeScript 类型检查、专项测试、完整自动化测试和生产构建均通过。
