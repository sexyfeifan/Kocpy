# Kocpy 0.1.6

0.1.6 完善既有备份接管的进度、可信度表达和项目收工判断。此版本仍未使用 Apple Developer ID 签名与公证。

## 接管进度与可信度

- 接管时显示素材卷、文件、已读取字节、速度、预计剩余时间和当前文件。
- “外部清单校验通过”“首次基线已建立”“已识别待建立基线”“外部清单不匹配”分别显示，不再统一归为“需要处理”。
- 整个项目和单日接管默认建立首次基线；仅在单张素材卡检测到清单时默认使用清单比对。
- 未验证导入使用独立状态，不伪装为失败，也不计为可信副本。
- 现有未验证或清单不匹配记录可逐卷完整读取并建立首次哈希基线。

## 日期与设备收工逻辑

- 项目外识别设备保留文件夹名称，例如“音频”，且只出现在实际发现它的拍摄日。
- 没有设备文件夹时显示“当天未发现素材 · 待确认”，不自动判定漏备份或当天未使用。
- 用户可分别确认“当天未使用”或“应该有素材”；只有后者会进入明确缺失数量。
- 素材卷达标文案明确表达“多少个素材卷达到副本要求”，避免与副本数量混淆。
- 项目 PDF 同步区分明确需处理和待确认单元。

## 已有记录整理

- 项目详情可重新分析已接管记录，按当前目录规则修正日期、设备、机位和素材卷信息。
- 同拍摄日且文件路径、大小、哈希完全一致的重复记录可合并为一个逻辑素材卷的多个物理副本。
- 整理过程只修改 Kocpy 元数据，不移动或删除原始素材文件。
