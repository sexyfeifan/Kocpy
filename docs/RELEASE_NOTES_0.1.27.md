# Kocpy 0.1.27

大型项目性能与备份优先资源调度版本。

- 权威工作区提交复用同一份规范化 JSON 完成摘要与落盘，避免在大型任务检查点中重复构造完整文档；原子发布、目录同步、备份轮换和 SHA-256 完整性验证保持不变。
- 素材索引加入持久化变更标记。只有索引版本、工作区修订、摘要和快照全部一致，且任务、项目、文件和实体表均未发生变更时，启动才走快速路径；任何被跟踪表的写入都会强制执行完整漂移检查。
- 索引发布失败时改用当前磁盘数据库的耐久回退点，不再在正常事务前额外导出一份完整内存快照。故障注入验证发布失败后，当前进程和重新启动均回到提交前状态。
- 素材库分页由深页 `OFFSET` 改为与项目、搜索和类型范围绑定的不透明游标。稳定排序避免同一时间创建的大量任务在翻页时重复或遗漏；修改筛选条件会回到第一页，旧范围游标不会被复用。
- 素材在线状态检查限制为最多 16 个并发路径探测，避免大型页面瞬时发起无界系统调用。
- 备份优先于代理转码：新的复制、恢复、失败副本重试或复校验开始前，正在运行的代理会安全暂停；备份队列空闲且工作区状态已经保存后，只恢复因“备份优先”暂停的代理。用户手动暂停的任务不会自动恢复。
- 代理列表明确显示“备份优先”暂停原因；暂停、恢复、失败重试和应用重启后仍保留可解释状态。
- 新增稳定游标、作用域失效、路径探测并发预算、代理暂停原因、索引回退、干净启动与大型工作区压力回归。

## 合成基准与限制

固定的隔离合成基准中，十万文件工作区检查点从约 520 ms 降至 369 ms，规范化状态由约 50.5 MB 降至 34.2 MB；同一份干净状态重新打开约 822 ms。十万文件索引重建约 1.17 s，峰值常驻内存约 912 MB。百万文件索引合成构建约 15.9 s，但基于 `sql.js` 的进程峰值仍约 7.83 GB，因此百万文件持续工作负载仍是已知资源边界，不应把本版本理解为已完成数据库架构迁移。

以上是本机隔离合成数据结果，不代表素材盘、NAS 或真实片场吞吐。复制与校验流程没有通过降低哈希、回读、落盘同步、源变化检查或物理副本标准换取速度。

## 升级与回退

0.1.27 首次打开会把可重建素材索引升级到 schema 6 并建立变更触发器；权威工作区格式和真实素材路径不变。升级失败时保留权威工作区，索引可以从其重建。升级前仍建议从“设置”导出本地数据备份。

0.1.26 不理解 schema 6 的索引快速路径，但仍可读取兼容 JSON。不要在旧版中新增、修改或删除记录后直接返回新版；新版会把这种情况视为待核对分叉，而不是静默合并。

本版本仍无 Developer ID 签名／公证；真实 NAS、拔盘、断电、睡眠、空间耗尽和全部文件系统矩阵未全面验证。最终发行附件、架构、测试结论与 SHA-256 以 [验证记录](VERIFICATION.md) 和 GitHub Release 实际附件为准。
