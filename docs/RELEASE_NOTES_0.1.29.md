# Kocpy 0.1.29

长期归档证据、周期提醒与安全修复版本。

- 工作区格式升级到 schema 2：归档健康、变化、提醒和复校验运行进入与任务／项目相同的权威提交边界；旧 `archive-health.json`、`archive-changes.json` 和 `archive-reminders.json` 一次性导入后仅作为兼容镜像。
- 每次复校验保存操作人、范围、基线摘要、逐素材卷结果、离线／身份未知目标、读取字节数和结果摘要。复校验从任务克隆开始，只有权威提交成功后才更新实时任务状态。
- 归档变化记录形成 SHA-256 摘要链；项目证据报告绑定工作区证据修订、全部运行、健康、变化、提醒和当前未解决问题，并附报告 SHA-256。历史差异不会被删除，后续成功修复或完整复校验会以追加事件关闭当前风险，避免旧问题长期误报。
- 周期提醒只根据最近一次成功的项目复校验推进；系统通知只更新通知时间，不扫描磁盘，也不把失败、离线或身份未知运行改写为成功。
- 归档修复要求实际操作人和风险确认；重新哈希健康来源、核对目标卷身份、唯一临时文件回读、保留损坏原件、原子发布与发布后完整回读。部分失败和异常中断把受控恢复事件、已保留损坏原件路径和实际结果写入追加式审计，成功后再执行整卷复校验。
- 冷归档恢复和工作站合并对导入的归档证据执行结构、数量、摘要和任务结果检查；项目内部记录删除同时清理相关复校验运行，并在确认范围中明确显示。
- 标签流水线新增安装包内归档证据专项：原生 arm64 与原生 Intel 均须通过健康／损坏识别、安全修复、故障保留、提醒语义和摘要防篡改检查。

## 升级与限制

首次启动会创建新的权威归档证据域，不移动、不改名、不重哈希或删除任何素材文件。复校验、提醒和报告导出是只读操作；只有用户明确确认“修复副本”时才写入所选归档目标，并保留原损坏文件。

本版本仍无 Developer ID 签名／公证。自动测试与本机验收使用仓库外隔离合成数据；真实 NAS、拔盘、断电、睡眠、空间耗尽、长期数 TB 归档和全部文件系统矩阵未因此宣称完成。最终发行附件、架构、测试结论和 SHA-256 以 [验证记录](VERIFICATION.md) 与 GitHub Release 实际附件为准。
