# Kocpy 0.1.21

可信状态、收工安全与媒体依赖分发维护版本。

- 项目覆盖、任务列表与详情、收工检查、单任务／每日／项目报告共用内容和副本判定。
- 区分源与副本哈希比对、外部清单校验、接管首次基线与仅识别结构；详情明确依据、最近记录时间和下一步。首次基线不证明接管前没有遗漏。
- 兼容紧凑日期与横杠日期，同一拍摄日不再重复统计；不迁移或改写旧任务。接管目标的现存容量与本次写入量分开，避免显示“已保存 0 B”。
- 优化项目 PDF 的状态列、路径列和分页；保留逐文件结果，同时说明文件条目校验不代替整卷清单与副本要求。
- 失败／取消／运行中的任务不会因残留已验证标记被算作已完成；休息／未使用声明不遮盖已有素材风险。
- 旧“允许额外文件”确认不能豁免新的缺失、大小不同或哈希不同；保留真实差异与审计。
- 不以不同 UUID 或路径证明物理独立。完整回读后的同次系统拓扑检查归并分区与 APFS 底层磁盘；网络、阵列和未知关系保守计数。旧校验记录保留，可重新校验在线目标更新证据。
- 双架构 FFmpeg 9.0.1 / x264 固定源码构建，移除 nonfree 运行时；完整许可证、对应源码、构建信息和摘要随包分发，并提供独立源码附件。Kocpy 的 MIT 许可不变，媒体运行时遵循 GPL-2.0-or-later。
- 修复成功媒体探测丢失元数据、预取消代理挂起及临时输出清理；代理发布禁止覆盖已有文件。
- 整理代理范围、收工条目、交接检查表、提醒和归档的间距与按钮。窗口常规最小 1080×720、比例范围 1.4–2.0，小屏适配可用区域；侧栏字号固定、独立滚动。使用说明默认折叠。
- 发布先完成双架构验收，再统一形成包含安装包、对应源码、SHA256SUMS.txt 的草稿，最终附件验收后公开。

0.1.20 候选在发布门禁发现后台覆盖统计遗漏，未公开安装包；原标签保留、不覆盖。上述修复均整合到 0.1.21。

没有 Developer ID 签名或公证。测试为隔离合成数据；系统拓扑不证明机箱、供电或灾备独立，校验完成不等于可以格式化原卡。真实 NAS／拔盘／断电／全部相机格式未全面验证，不承诺零缺陷。精确验收记录见 [验证记录](https://github.com/sexyfeifan/Kocpy/blob/main/docs/VERIFICATION.md)。
