# Kocpy 0.1.12

0.1.12 增加“操作人有意剔除素材”的经审计 MHL 修订流程。它用于隐私、授权限制或交付范围等极端情况，不会把普通漏拷或损坏伪装成完整副本。此版本仍未使用 Apple Developer ID 签名与公证。

## 经审计修订 MHL

- 仅当外部清单差异为“纯缺失”，且不存在额外文件、大小不同或哈希不同时显示修订入口。
- 用户必须填写剔除原因、勾选重要风险确认，并准确输入 `修改 MHL`；主进程会再次验证全部条件，不能绕过界面直接调用。
- 提示明确说明：修订后的绿色状态只证明“保留素材集合”完整，不再证明它与原数据卡的全部内容一致。
- Kocpy 不会删除任何素材文件，也不会用清单修订跳过大小或校验值异常。

## 原始证据与安全写入

- 修改前计算原始 MHL 的 SHA-256，并将原文件复制到素材卷内隐藏的 `.kocpy-manifest-history` 审计目录；该目录不参与素材统计，并会随素材卷一同迁移。
- 审计副本必须回读得到相同 SHA-256，才能继续生成修订清单。
- 修订后的 MHL 必须保持原校验算法、准确减少全部确认项并通过重新解析，随后才原子替换生效文件。
- 项目审计日志保存剔除数量、原因、时间、原始 MHL SHA-256 和审计副本位置。
- 修订后自动完整重读并校验当前素材卷；通过后显示“修订 MHL 校验通过 · 排除 N”。点击绿色状态可在 Finder 中定位修订前的原始 MHL。

## 界面细节

- 修复缺失文件与修订清单分为两个独立操作，避免把“找回素材”和“重新定义交付集合”混淆。
- 重要确认复选框恢复横向对齐，风险说明、原因和确认文字保持清晰层级。
- 软件内使用说明和 GitHub 用户手册已加入完整操作边界与审计说明。

## 验证

- 新增 MHL 修订成功测试：原始清单审计副本保持逐字节一致，修订清单排除指定记录，并通过完整导入校验。
- 新增拒绝测试：待排除路径不在原清单时，MHL 保持不变且不会创建审计目录。
- 完整自动化测试、TypeScript 类型检查和生产构建均通过。
