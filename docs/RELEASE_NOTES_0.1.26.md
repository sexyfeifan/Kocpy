# Kocpy 0.1.26

工作区持久化、迁移与中断恢复加固版本。

- 明确任务与项目的 JSON 工作区状态是业务权威，SQLite 是可核对、可删除重建的素材索引；启动时不再按时间猜测并合并两个事实源。
- 权威状态加入格式版本、单调提交修订、提交时间、SHA-256 摘要以及任务／项目删除墓碑。旧索引或旧备份不会重新带回已经删除的任务或项目。
- 任务与项目写入统一经过串行工作区服务。任务和项目同时变化、重复请求或并发提交时，不会由后一项写入覆盖另一业务域。
- 发布顺序为：先原子写入权威状态，再更新 0.1.25 兼容镜像，最后同步 SQLite。正在传输时仍按原检查点频率保存权威状态，但把重复的大型兼容镜像写入延后到任务结算或下一次明确状态变化，避免热路径重复写整份记录。若在任一阶段中断，下次启动按修订和摘要修复镜像或重建索引，不把索引失败误报为素材文件丢失。
- 首次升级时，有效的 `tasks.json`／`projects.json` 是迁移依据；SQLite 只在对应 JSON 镜像不存在或不可恢复时补位。显式空数组也是权威，不会因旧索引残留而复活记录。
- 权威主文件损坏时会比较有效备份和 SQLite 中的完整工作区快照，选择修订最高且摘要匹配的版本。同一最高修订若出现多个内容冲突但各自摘要有效的状态，或兼容镜像标记比可恢复权威状态更新，都会停止自动选择；所有权威副本均无效时也不会从旧兼容镜像猜测恢复。
- 运行中若权威记录因系统盘空间或权限问题无法落盘，Kocpy 会请求暂停仍在复制／校验的任务并明确提示“不要清卡”；辅助镜像或索引失败则区分提示为“权威记录已保存、辅助数据待恢复”。
- 检测到旧版应用或外部程序在当前修订后改写兼容镜像时停止自动合并，同时保留两侧数据并提示先保存应用数据与诊断信息。
- 启动被权威状态损坏、未知新格式或旧版写入分叉阻断时，会在应用数据目录生成不含任务、项目、素材路径和文件清单的 `workspace-startup-error.json`，记录版本、错误及各恢复文件是否存在，便于在不暴露素材的前提下处理。
- 脱敏诊断包加入工作区格式、修订、摘要前缀、任务／项目／墓碑数量和索引统计，不包含素材内容、完整路径或文件清单。
- 新增迁移、空 JSON、SQLite 补位、并发双域提交、相同检查点、任务／项目删除、防复活、索引漂移、权威写入失败、镜像中断、索引中断、未知新格式和全部权威副本损坏回归。

## 升级与回退

0.1.25 数据会在首次启动 0.1.26 时原地建立带摘要的工作区状态，同时继续维护原 `tasks.json` 和 `projects.json`，不移动或重写素材文件。升级前仍建议从“设置”导出本地数据备份。

0.1.25 可以读取 0.1.26 维护的兼容镜像，但它不了解工作区修订和墓碑。不要在 0.1.25 中新增、修改或删除记录后直接返回 0.1.26；0.1.26 会将这种情况视为不安全的分叉并停止自动合并。需要回退写入时先导出备份，并保留完整应用数据目录供人工核对。

本版本不改变素材复制、独立回读、MHL 差异和物理副本安全门槛，也不修改真实素材。仍无 Developer ID 签名／公证；真实 NAS、拔盘、断电、空间耗尽和全部文件系统矩阵未全面验证。最终发行附件、架构、测试结论与 SHA-256 以 [验证记录](VERIFICATION.md) 和 GitHub Release 实际附件为准。
