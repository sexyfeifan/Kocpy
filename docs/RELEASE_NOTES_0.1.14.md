# Kocpy 0.1.14

0.1.14 是面向现场数据安全、异常恢复和长期记录可信度的加固版本。本版本不改变外部清单差异的严格含义，也不会自动修改素材；重点是让“成功”“安全副本”“可恢复记录”和“可导出归档”拥有一致、可验证的判定依据。

## 复制与完成判定

- 修复慢速目的地从快速分发中分离后可能使用可变全局偏移写入的问题；每个数据块现在固定使用读取时的绝对偏移。
- 复制期间周期性检查素材源与所有在线目的地的卷 UUID/身份；记录过 UUID 的磁盘若当前 UUID 缺失或不同，立即停止。
- 全部文件复制后重新扫描素材源。新增、删除、大小或修改时间变化都会阻止成功状态。
- 最终文件发布后同步文件与父目录，并保留源文件权限、访问时间和修改时间。
- 完成动作中的“推出”改为推出素材源，不再推出刚写好的备份目的地。
- 批量安全推出会重新检查素材卡身份与当前文件清单，同时要求不存在未解决的外部清单差异。

## 记录、数据库与冷归档

- JSON 主记录损坏时不再覆盖健康 `.bak`。
- SQLite 打开与恢复均执行 `PRAGMA integrity_check`；损坏行不再静默跳过。
- 任务头与文件明细分表保存，避免在任务 JSON 中重复存储海量文件记录；保留原始文件顺序。
- 运行中进度只写轻量 JSON 检查点，任务结算后更新索引，避免每秒完整导出大型数据库。
- 启动时合并 JSON 镜像与索引记录，按最新检查点保留并集；只有发现差异时才重建索引。
- 应用退出前同时等待 JSON 和 SQLite 写入队列落盘。
- 工作站导入完成后同步重建索引；新版包要求完整性签名并检查绝对路径、相对路径越界和文件副本结构，旧版 schema 1 包继续兼容。
- 冷归档先写临时文件、同步落盘、重新解压并校验，再原子发布和移除热记录；恢复增加压缩包大小、解压输出和任务结构限制。

## 清单、报告与归档修复

- MHL/ASC MHL 使用已校验目的地的真实最终路径；重名策略改名后不再错误记录源路径。
- 未完成任务、没有完整已校验副本或存在未解决外部清单差异时，拒绝导出 MHL/ASC MHL。
- 项目归档包要求每个素材卷满足项目的物理独立副本与清单要求，否则明确拒绝生成。
- PDF、拍摄日报和项目报告不会把未解决清单差异显示为成功。
- 外部清单现在拒绝重复路径、目录越界路径和混合哈希算法，避免模糊解析。
- 归档副本修复前重新哈希健康副本并确认目标卷身份；采用唯一暂存文件、同步元数据和父目录，准确记录保留的损坏文件数，完成后执行整任务复校验。
- MHL 修订的审计副本与生效清单替换均同步父目录，降低异常断电后目录项丢失风险。

## 诊断、可靠性与界面

- 可靠性验收的大文件和小文件在回读前执行文件同步；测试仍只在用户选择的临时目录运行并自动清理。
- 脱敏诊断包进一步哈希化任务名、源名称、卷名、目的地标签与性能测试路径。
- 软件内使用说明更新到 0.1.14，所有模块保持默认折叠，只有用户点击后展开。
- 默认与最小窗口继续根据当前显示器工作区域计算；左侧功能按现场流程排序并在紧凑高度保留全部入口。
