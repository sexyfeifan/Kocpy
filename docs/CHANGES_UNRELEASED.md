# 未发布改动

以下源码改动纳入 0.1.49；准确安装包、公开状态和验收范围以[同版发布说明](RELEASE_NOTES_0.1.49.md)、[验证记录](VERIFICATION.md)及 GitHub Release 为准。源码实现与测试不等同于最终安装包验收完成。

## 界面布局

- 项目卡片、摘要、表单与操作区补足内边距；长标题、路径与密集控件在可用宽度内换行。
- 保持侧栏文字和图标尺寸，使用滚动和响应式布局，不以缩小整个界面解决拥挤。
- 深浅主题使用同一控件边界与状态语义，数据风险和确认要求不受外观变化影响。

## 当日临时设备

- 从具体拍摄日直接新增设备或机位，填写实际操作人后选中用于本次备份；同一保存幂等，不重复添加。
- 仅记录所选日期计划，不扩展常驻设备、不提前创建空目录；取消备份仍保留明确已保存的日计划。
- 日计划恢复休息日、撤销父级未使用豁免均保留审计；其他已知机位维持原决定。明确未分机位与命名机位可同时显示。
- 名称、路径别名和自定义命名冲突在保存前拒绝；换日期后不能继续使用不属于新日期的临时设备。

## 混合日期范围与证据

- 默认整卡；拷贝前只读查看日期线索，再由用户逐组确认日期和本次范围。
- 跨目录关联文件成组；未知／共享文件、摄影机包、关联不明的独立录音保守保留，不因未选日期被静默遗漏。
- 源文件逐一读取 SHA-256；历史跳过依据要求同项目当前在线副本重新验证及足够独立性证据。其他未选内容必须明确确认风险。
- 开始与完成前重新核对冻结源范围；记录包含、排除、确认人、日期和历史依据。源素材、原目录和原 MHL 均不改写。
- 部分范围不计为整卡完整副本，不获得清卡资格；任务、报告和随盘范围声明传递此边界。日统计只包含本次路径，未知日期留在任务日待确认。
- 整卡后每日交付复用保守闭包；部分范围任务不能冒充整卡再次生成交付。旧待续交付可保留读取，但范围改变时阻止恢复并要求重新分析新建。
- 新的待执行交付只记录实际已存在目录的身份，避免在 Media 目录尚未创建时提前写入不成立的子目录绑定。
