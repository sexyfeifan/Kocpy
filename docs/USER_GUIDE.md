# Kocpy 0.1.25 使用手册

软件内“使用说明”的所有模块默认保持折叠。0.1.19 将本页说明移至顶栏右侧问号图标（悬停提示“本页使用说明”）；只有用户点击后才打开对应模块。侧栏仍保留完整使用说明入口，不自动展开工作区。

Kocpy 是面向片场与工作室的 macOS 素材备份、校验、接管和长期归档工作台。它的核心目标是可靠接收与规范交付，不会修改源素材，也不会代替剪辑软件。

## 1. 第一次使用

### 只想安全备份：三步即可

1. 点击“新建备份”，保持默认“普通备份”，选择或拖入素材卡／文件夹。不需要先创建项目。
2. 选择存放副本的父目录。默认“按次保存”自动添加时间戳；想保留源文件夹名称时选择“保留源文件夹（镜像备份）”。核对页面列出的最终路径。
3. 检查来源、容量和保存路径，然后开始。高级选项默认折叠，哈希与逐目标独立回读始终开启；等待复制和校验全部完成后再查看结果与下一步。

普通备份是工作模式，按次保存／保留源文件夹是其中的目录组织方式，两者不是三个互斥工作模式。镜像不是删除式同步，不移除目的地额外文件。只有需要拍摄日、机位和收工管理时才选择“项目备份”。

容量读取失败会显示“待引擎预检”，不会显示已通过；实际写入前仍逐目标核对容量与临时发布余量。开始前不凭目的地数量或不同 UUID 宣称已满足独立副本要求，完成后再按存储证据计数。

### 0.1.25：界面、键盘与窗口一致性

- 全应用按钮分为主操作、普通操作、次要操作和危险操作；图标按钮提供明确名称，禁用状态保留未满足条件或正在处理的原因。
- 普通弹窗与危险确认打开后，焦点进入当前窗口，Tab／Shift-Tab 不会跳到背后页面；Escape 只执行可用的取消或关闭，退出后返回原来的按钮。危险操作仍须完成其独立确认，不因键盘优化而降低门槛。
- 错误、完成、警告、空状态和可信度使用不同语义。媒体预览是非模态检查器，可在查看媒体信息时继续操作素材列表。
- 最小窗口保持侧栏文字和图标原尺寸，侧栏导航与主内容分别滚动。表格、弹窗底部操作、长中文／英文／路径在空间不足时换行或滚动，不缩小到难以辨认。
- 深色和浅色主题共同覆盖背景、边框、表单、焦点、禁用、成功、警告和错误状态。软件内完整说明只有用户点击侧栏“使用说明”后出现；各页面的简要说明只有点击顶栏问号后打开。

### 0.1.21：先理解不同的证据

- 内容校验：Kocpy 传输比对源与目的地哈希；外部清单接管按清单条目完整比对；首次基线只证明接管时现存内容被读取，不证明接管前完整。
- 任务完成：正在运行、暂停、失败、取消或仅导入结构都不计为已完成，即使保存着某个目标以前的校验记录。
- 副本达标：完成且没有未处理清单差异后，再按项目要求与可证明的存储关系判定。详情列出依据、最近校验记录时间与下一步，项目和报告使用相同规则。
- 人工确认仅作用于允许的具体差异：“允许额外文件”不豁免新的缺失、大小或哈希差异。重读清单发现新问题后仍需处理，不通过隐藏红色提示来判安全。

“目标通过校验”表示该目标已独立回读且哈希一致；“可计数副本”还要判断目标之间的存储关系。两个文件夹、两个分区或两个不同 UUID，可能仍共用同一块物理磁盘。

### 0.1.23：项目日常操作与证据版本

- 每日计划中的“应该有素材”“当天未使用”“休息日”和恢复待确认都需要填写实际操作人；每次决定追加日期、设备/机位、操作人、时间和所依据的项目规则版本。空白状态继续保持未知。
- 临时加入当天的设备或机位只作用于所选拍摄日，不会把一次临时航拍或录音设备永久写进全部拍摄日。
- 新建项目会建立第一个规则版本；修改项目名称／拍摄周期（会改变目录或日程）、设备、机位、目的地、副本数、命名规则、完成动作或检查表时，必须填写修改人并追加新版本。仅修改制作类型、预计卷数、管理起始日或人员等说明信息不会制造伪版本。
- 应用模板前仍逐项预览；应用时必须填写操作人，并记录模板名称、模板版本、覆盖字段、真实前后值和结果规则版本。
- 同一素材卷的首次任务、失败目标重试和恢复尝试共享逻辑素材卷身份。项目卡片、收工矩阵和素材卷明细按逻辑素材卷统计，不因重试次数增加素材卷数；明细会显示尝试次数。
- 交接可选择单个拍摄日或整个项目，保存时冻结当时的规则版本、逻辑素材卷数、达标数、待处理和待确认单元。后续修改规则不会改写已保存交接。

规则版本和交接记录是本地审计证据，不是第三方数字签名。它们用于避免后续配置覆盖历史语义；仍需结合素材哈希、物理磁盘关系、报告和现场交接共同判断安全。

Kocpy 在完整校验后检查同一次在线存储拓扑。明确不同底层磁盘才增加独立副本数；NAS、未知阵列、旧任务缺少拓扑或不同检查批次不拼接推断。至少一个通过校验的目标可计为一份副本，但不凭未知关系增加第二份。旧任务因此显示“证据不足”不等于文件损坏：连接原目标后重新校验可以更新关系，原校验记录仍保留。

收工状态不会被“休息 / 未使用”掩盖：这些标记只适用于没有记录素材的单元。若该单元已有素材，仍需要解决校验、清单或副本不足问题。系统拓扑只反映系统可见存储关系，不保证机箱、供电或异地容灾独立。

### 窗口与媒体组件

窗口在正常状态保持 1.4–2.0 宽高比，常规屏幕最小 1080×720；小屏以可用显示区域为限。侧栏文字和图标不缩小，下方功能通过滚动访问。代理范围和交接／归档按钮已调整留白与换行。

内置 FFmpeg 与 x264 的完整许可证、对应源码、构建脚本与摘要位于应用资源的 ffmpeg 目录，也可从同一 GitHub Release 获取对应源码包。无需用户另行安装 FFmpeg。Kocpy MIT 许可与独立媒体组件许可分别适用。

需要专业项目管理时，推荐的现场流程：

1. 创建拍摄项目，填写拍摄周期、设备、机位和收工所需副本数。
2. 连接素材卡以及至少两块不同的物理目的地磁盘。
3. 点击“新建备份”，选择来源、项目、拍摄日期、设备和机位。
4. 检查来源文件数、实际素材量、目的地容量和磁盘状态。
5. 开始备份，等待紫色复制阶段与绿色独立回读校验全部完成。
6. 在拍摄项目中检查当天的日期 × 设备/机位矩阵。
7. 导出报告并安全推出已经完成的设备。

Kocpy 不会默认“插卡即写入”。识别结果和目的地必须由用户确认后才会开始复制。

## 2. 新建备份与命名

### 普通备份

在“普通备份”的“设置目的地”选择“按次保存（推荐）”，素材会保存到以 `素材源文件夹名_时间戳` 命名的任务目录。例如：`FX3_A001_20260830143000`。时间戳在开始时生成，内部文件名和子目录结构不变；任务显示名称不替代源文件夹名称。

### 镜像备份

在“设置目的地”选择“保留源文件夹（镜像备份）”。从 0.1.17 起，新任务会把所选源文件夹这一层也放入目的地，不添加随机码或时间戳。

例如，选择源 `/Volumes/CARD/20260825_项目`、目的地 `/Volumes/Backup/交付项目`，最终路径为 `/Volumes/Backup/交付项目/20260825_项目`。目的地选的是父目录，不要先进入一个同名的空文件夹，否则会再嵌套一层。选择素材卡根目录时，保留的这一层为素材卡卷名。

这里的“镜像”表示保留目录与名称，并不是删除式磁盘同步：不会删除目的地已有的额外文件。同名同内容需核验，同名不同内容按冲突策略处理，不静默覆盖。

升级前创建、没有新布局标记的旧镜像任务在恢复和重试时继续使用旧落点；升级不会移动已经存在的副本。需要新布局时应新建任务并检查最终路径。一次选择多个同名源文件夹会被拒绝，请分批备份到不同目的地，避免意外合并。

### 扫描统计是什么

数字分别表示视频、照片／RAW、音频、其他／附属文件的数量，单位为“个文件”，不是素材卷号。根据扩展名分类，RAW 与对应 JPG 分别计数。XML、MHL、LRF 等附属文件可能计入“其他”，仍会按备份规则复制；系统索引文件及设置排除的隐藏文件不参与备份。汇总容量是本次选中来源的文件容量，不是多目的地总写入量。

### 目的地

- 可选择 1–4 个目的地。
- 源与目的地都支持点击选择或从 Finder 拖入文件夹。单个文件、无效拖入项会显示具体错误，不再静默无反应。
- 目的地统一选“存放副本的父目录”。选择后和开始前都能看到每个来源的最终路径；多目的地最多 4 个。
- 同一物理磁盘上的多个文件夹不算多份独立安全副本。
- 网络目录必须先在 Finder 中挂载；SMB/NAS 中断后可在恢复中心继续处理。

## 3. 传输、校验与恢复

紫色进度表示复制，绿色进度表示目标副本的独立回读校验。“已保存”表示当前有效素材量，“本次写入”表示本轮实际写入量，两者在断点恢复或目标重试时可能不同。

预计时间仅属于当前阶段，不包含尚未开始的后续回读；预检或测速不足时显示“—”。暂停立即清除速度与预计时间，继续后重新采样，不把暂停时间算进传输速率。未到100%的阶段不会四舍五入成100%；字节100%仍需等待文件收尾、哈希核对和最终状态。暂停／继续按钮先显示命令处理中，再使用后台实际状态，不提前显示成功。

再次校验期间显示当前回读阶段，不将上次完成的性能总结混作本次结果；等本次结束后再查看总结、校验依据与副本要求。单任务PDF中，目的地标题与其表格一起分页，避免标题单独留在上一页。

文件较多时，单任务PDF会跨页重复表头，使用适合打印的平面分区，保留全部明细；HTML视图仍保留卡片样式。报告记录的是该次任务结果，不代替重新读取磁盘进行校验。

0.1.15 起，传输列表会按任务内容显示素材类型图标：场记板表示视频、相机表示照片/RAW、波形表示音频、叠层表示混合素材、存储卡表示其他素材。图标颜色表达任务状态，而不是素材类型：紫色为等待/复制/校验中，绿色为完成，黄色为暂停或未验证，红色为失败，灰色为取消。

每个非紧凑任务条目会完整显示源路径和所有目的地的最终路径。长路径自动换行，不以省略号隐藏；点击任一路径可在 Finder 中显示。若同名处理改变了目的地名称，这里显示实际写入并校验过的最终路径。任务搜索也会匹配源路径和目的地路径。

任务可以暂停、继续和取消。异常退出、素材源失联、目的地离线或校验未完成时，到“恢复中心”选择：

- 从安全检查点继续；
- 扫描并复用已有断点文件；
- 只重试失败目的地；
- 不重新复制，直接重新校验现有副本。

已经成功且通过校验的目的地不会因为单个目标失败而被重新写入。

### 0.1.19：磁盘停止后的处理流程

1. 在恢复中心或任务详情点击“检查并恢复”，阅读原错误与处理建议。
2. 点击“只读检查连接与身份”。它显示记录身份、当前 UUID、实际挂载点、目录权限及当前可用空间，不创建文件，不改写任务，也不代表素材哈希校验通过。
3. 所需路径可访问、身份检查通过后，勾选核对确认，再点击“重试未通过目标”。后台会再次检查；真正写入前仍执行完整预检、断点/已有文件验证和独立回读。入队不等于任务完成。
4. 若身份无法读取或磁盘离线，先检查原盘连接、挂载与权限，再重新只读检查。若确实更换或格式化磁盘，使用“另建备份任务”选择正确目的地；保留旧记录，不允许覆盖旧 UUID 来消除警告。

旧版本曾对任意子目录直接查询磁盘身份，查询失败可能被误报为“UUID 已变化”。0.1.19 改为查询该路径实际所属设备；原盘身份一致时可恢复旧失败任务，不必删除项目重做接管。更名导致旧路径失效、真实换盘和素材源变化仍需处理，不能仅凭盘名判断安全。

只保存旧设备标识、未保存 UUID 的历史任务会明确显示较弱的旧身份匹配，不宣称历史完整性已得到证明。空间显示是当前可用量，精确写入余量仍以正式预检为准。外部接管记录继续使用首次基线或外部清单处理，不走普通复制恢复。没有完整文件哈希基线时，“重新校验”不会将任务标为安全。

复校验会重新检查原盘是否在线，成功后清除旧任务错误。为避免交叉修改文件记录，需要先完成当前传输队列再发起复校验。

### 实时进度与速度

0.1.17 修复任务详情使用旧快照的问题。详情窗口与拍摄项目的素材卷明细会随任务更新，不需要关闭重开；点击素材卷名称可进入详情。大文件复制进度按已确认写入字节更新，不必等整个文件结束。暂停／继续状态立即推送，按钮在命令确认期间显示等待反馈；正在执行的小块读写或安全落盘可能需要收尾。

界面区分源文件哈希读取、复制和目的地独立回读校验。全新文件可边复制边计算源哈希，减少一次完整源读取；已有文件、断点和仅重试失败目标仍先计算源哈希进行比对。SHA-256／SHA-1／MD5 和目的地独立回读要求均未降低。

速度对比应分开看“复制阶段”与“复制加完整校验”。多目的地总写入量、介质连接方式、小文件数量以及校验算法都会影响耗时。不能将 Kocpy 完整校验任务的总用时直接等同于 Finder 单纯复制的用时；本地小样本优化结果也不代表所有外接盘或 Intel 实机。

### 0.1.14：完成判定与记录恢复

- 复制期间每 15 秒重新确认素材源和目的地卷身份；记录过 UUID 的卷若当前无法提供同一 UUID，也会停止，不会退回到同名路径判断。
- 全部文件复制后会重新扫描素材源。若出现新增、删除、大小或修改时间变化，任务不会显示成功，应确认素材卡已停止写入后重新备份。
- 最终文件会保留源文件权限与修改时间，并在发布后同步文件及父目录；数据库和 JSON 记录也采用临时文件、同步和原子替换。
- SQLite 索引损坏时只恢复通过完整性检查的备份；JSON 镜像与索引会按最新检查点合并，避免一侧较旧导致任务消失。
- 安全推出前会重新核对素材卡身份与文件清单；自动完成动作推出的是素材源，而不是刚写好的目的地。

## 4. 接管既有备份

项目卡片中的“接管既有备份”用于把 Kocpy 安装前或其他工作站完成的素材纳入项目记录。支持三种范围：

### 0.1.24：先确认映射，再写入记录

选择目录后，Kocpy 先生成当前文件清单与识别映射摘要，逐卷显示拍摄日期、设备、机位、素材卷名称、文件数和相对根目录。日期、设备或卷名无法判断，或两个目录将落到同一“日期／设备／机位／卷名”时，必须在预览中修正；未解决映射不会写入项目。

开始接管时 Kocpy 会重新扫描并比对预览摘要。全部文件读取、哈希或外部清单比对完成后，数据库写入前再扫描一次；中途新增、删除或改变文件会使整批接管停止，不留下半套记录。预览较早、目录已改变时，应点击“重新识别范围”并重新核对。

接管前还须确认副本关联规则：只有文件路径、大小和完整哈希全部一致的不同目录，才会关联为同一逻辑素材卷；这不会把相同内容误算成多张卡。同一块物理磁盘上的多个目录不构成多份物理独立副本。接管会记录当前卷 UUID，但没有同次存储拓扑证据时仍保守显示物理独立性待确认。

任务详情的“接管与维护审计”按时间追加接管、首次基线、外部清单修复／修订／复校验、额外文件确认和重定位记录，包含当时路径、证据摘要、时间和操作人。操作人优先使用设置中的“默认操作人”，未设置时明确记为“本机用户”；后续操作不会覆盖旧路径或旧结论。

### 单张素材卡

选择一个实际素材卷目录。Kocpy 把它作为一个逻辑素材卷接管。

### 单日所有机位

选择一个拍摄日目录。其下一层按设备/机位识别，再下一层按素材卷识别。例如：

```text
20260825/
├── FX3/
│   └── Untitled_202608260150/
├── ZVE1/
│   └── ZVE1_202608260152/
└── 音频/
    ├── 1/
    └── 2/
```

项目配置中没有的文件夹名称会保留为实际设备名称，例如“音频”，不会统一显示成“外部素材”。

### 整个项目

选择项目根目录。Kocpy 先识别有效拍摄日期目录，再按“日期 → 设备/机位 → 素材卷”展开。目录结构应尽量与项目创建时的规则一致。无效日历日期不会被当成拍摄日。

### 接管可信度

- **外部清单通过**：MHL/SHA 清单与当前文件完全一致，可作为可信副本。
- **接管时基线**：Kocpy 在接管时完整读取文件并建立哈希，只证明接管当时的内容状态。
- **仅导入结构 / 未验证**：只记录目录和文件信息，不计入安全副本。
- **清单差异 · 缺少 N**：外部清单列出了文件，但当前卡卷目录中不存在；需要回到其他健康副本查找或重新复制。
- **清单差异 · 额外 N**：当前卡卷目录中存在清单没有记录的文件；应确认它是清单生成后新增的有效素材，还是误放文件。
- **清单差异 · 大小不同 N**：路径相同但文件大小已经变化；不能作为安全副本。
- **外部清单格式不支持**：清单存在，但没有可读取的 MD5、SHA-1、SHA-256 或 Kocard 十进制 xxHash32 条目。

接管读取时会显示素材卷、文件、已读取字节、速度、预计剩余时间和当前文件。关闭窗口前应等待读取完成。

### 0.1.13：处理外部清单差异与经审计修订

素材卷明细中的红色“清单差异”状态现在可以点击。弹窗会列出全部缺失、额外、大小不同和校验值不同的相对路径，并可打开素材卷目录、外部清单或具体文件在 Finder 中的位置。

若“缺失”和“额外”同时出现，0.1.13 会把它显示为需要分步处理的混合差异：先补回清单记录的缺失文件，再重新完整核对，最后处理仍然存在的额外文件。补回操作成功后不会因为额外文件尚未处理而显示成调用错误；弹窗会原地刷新并明确说明剩余项目。

当缺失路径带有 `(1)` 等系统常见重名后缀，而同目录存在名称相近的额外文件时，弹窗会显示“疑似同名冲突”并分别列出清单记录大小与当前文件大小。此提示仅解释可能成因，不会根据名称自动判定两个文件相同；0 字节额外文件会被明确警告为不能替代有效素材。

#### 缺失文件

1. 点击红色的“清单差异 · 缺少 N”。
2. 检查完整缺失列表，确认当前目录确实不含这些文件。
3. 勾选修复确认，点击“选择健康副本并修复、校验”。
4. 选择同一张素材卡、对应素材子目录或其上级目录。例如清单记录 `DCIM/100MSDCF/DSC06117.ARW` 时，可以选择原卡根目录，也可以选择重组后的 `100MSDCF` 或包含它的上级目录。
5. Kocpy 根据清单路径寻找唯一的完整映射。若找不到完整映射，或同时存在两组不同的完整候选，修复会停止并要求选择更精确的目录，不会猜测。
6. 映射确定后，Kocpy 检查目标空间，并校验全部候选文件的路径、大小和清单哈希；任何一项不符都会在写入前停止。
7. 全部候选通过后，Kocpy 先将所有文件写入目标卷上的隐藏暂存目录并再次校验，再以“不覆盖已有文件”的方式统一提交。任一步失败都会回滚本次新增文件。
8. 提交完成后自动执行整卷外部清单校验。若只剩额外文件，缺失文件的修复结果会保留，弹窗原地进入额外文件处理步骤；全部差异处理完成后才恢复绿色状态并重新计入收工副本。

#### 操作人有意剔除的缺失素材

在隐私、授权限制或交付范围等极端情况下，清单记录的文件可能由操作人主动剔除且不应补回。只有当前差异为“纯缺失”，不存在额外文件、大小不同或哈希不同时，Kocpy 才显示“修订 MHL”入口。

1. 逐项核对缺失列表，确认不是漏拷、损坏或误删。
2. 填写 2–500 个字符的剔除原因。
3. 勾选重要风险确认，明确理解修订后的绿色状态只证明“保留素材集合”完整，不再证明与原数据卡全量一致。
4. 输入指定文字 `修改 MHL`，点击“修订 MHL 并重新完整校验”。
5. Kocpy 先计算原 MHL 的 SHA-256，并将原文件保存到当前素材卷内隐藏的 `.kocpy-manifest-history` 审计目录；该目录不会参与素材统计，随素材卷迁移时仍能保留。审计副本回读哈希一致后才生成修订清单。
6. 修订清单必须保持原算法、准确减少全部确认项并通过重新解析，随后以原子替换方式生效。
7. Kocpy 对当前素材卷重新逐文件计算校验值。通过后状态显示“修订 MHL 校验通过 · 排除 N”；点击该绿色状态可在 Finder 中定位修订前的原始 MHL。

此功能不会删除任何素材文件，也不能用于掩盖大小不同或校验值不同。项目审计记录会保存剔除数量、原因、时间、原始清单 SHA-256 和审计副本位置。

#### 额外文件

1. 点击红色的“清单差异 · 额外 N”，逐项在 Finder 中检查。
2. 若文件是误放内容，请在 Finder 中自行移出素材卷目录，然后点击“重新完整核对”。Kocpy 不会擅自删除或移动素材。
3. 若文件确属有效素材、只是原 MHL 未记录，可直接在差异弹窗点击“建立当前完整哈希基线”。Kocpy 逐文件读取完成后，再勾选确认并选择“确认额外文件并采用当前基线”。
4. 此操作不会修改原 MHL；原始差异、确认时间与说明会保留在 Kocpy 审计记录中。此后该基线可计入收工状态，但刷新发现差异内容变化时会重新要求处理。

0 字节文件通常是中断生成、复制遗留或占位文件，不应仅因名称与缺失项相似就确认保留。优先在 Finder 中隔离检查；Kocpy 不会自动删除、移动或把它当成同名缺失文件。

未被明确确认为“操作人有意剔除”的缺失文件，以及所有大小不同或校验值不同，均不能通过普通确认跳过。手工从其他工具修复后，可随时点击“重新完整核对”。弹窗会显示实际采用的“健康副本目录 → 清单目录”映射，错误提示只保留可操作的业务原因，不再显示 Electron IPC 包装文字。

## 5. 0.1.8：刷新接管信息

旧版本可能把同一个实际目录的多次接管保存成多条素材卷记录，也可能把“日期/设备父目录”连同其下的真实卡卷重复保存为一个素材卷，造成素材卷数、文件数、容量和收工进度重复累计。0.1.8 的“刷新接管信息”会同时修复这两类记录，并按卡卷根目录中的外部清单重新判断真实差异。

### 使用步骤

1. 打开“拍摄项目”。
2. 进入需要修正的项目详情。
3. 点击“刷新接管信息”。
4. 阅读预览：待修正元数据、待合并重复素材卷、误识别父级汇总、外部清单差异、离线来源和仍需建立基线的数量。
5. 确认刷新，完成后项目卡片、日期设备矩阵和素材卷明细会立即重新计算。

### 刷新会做什么

- 根据现有目录规则重新识别日期、设备、机位和素材卷名称。
- 同一绝对路径的历史记录只保留一个逻辑素材卷。
- 若日期/设备父目录的文件集合恰好等于下层真实素材卷的并集，自动移除该父级汇总记录，只保留下层真实素材卷。
- 保留可信度更高、状态更完整的有效记录与目的地信息。
- 清理同一路径的重复项目绑定记录。
- 不同路径只有在每个文件都有完整且一致的哈希时，才会合并为同一素材卷的多个副本。
- 只读取素材卷根目录中的 MHL/SHA 清单，支持 MD5、SHA-1、SHA-256，以及 Kocard MHL 使用的十进制 xxHash32。
- 用清单路径和文件大小区分“缺少、额外、大小不同”，并在素材卷明细中显示准确数量。

### 刷新不会做什么

- 刷新阶段不重新计算素材哈希；因此它会核对清单路径与大小，但不会把“结构一致”冒充成一次新的完整哈希校验。
- 不重新复制、移动、改名或删除任何素材文件。
- 不修改由 Kocpy 正常复制产生的原生任务。
- 不会自动接管后来新加入、此前从未记录过的文件夹；这种情况请再次使用“接管既有备份”。
- 来源磁盘离线时不会丢弃原记录；该来源会保留，重新连接后可再次刷新。

例如，同一路径被旧版本接管 5 次，界面曾显示 `2 / 5 个素材卷达到 1 份物理独立副本`。刷新后它会恢复为 1 个唯一素材卷；如果该记录已有一份可信副本，收工状态会显示 `1 / 1` 或“已满足收工要求”。

## 6. 项目矩阵与收工状态

项目详情按“拍摄日期 × 设备/机位”显示素材卷、文件、容量和安全副本状态。

- **已满足收工要求**：该单元的每个已发现素材卷都达到项目要求的物理独立副本数。
- **应该有素材 · 缺少备份**：当天明确计划使用该设备，但没有发现记录。
- **当天未发现素材 · 待确认**：Kocpy 没有发现记录，也没有足够信息判断设备是否使用。
- **当天未使用**：由用户确认该设备当天没有拍摄，不再计入收工缺口。
- **休息日**：整天不计入收工缺口。

“没有备份”和“当天未使用”不能由文件夹缺失自动等同。Kocpy 默认保留“待确认”，需要用户根据现场记录标记。

项目卡片中的素材覆盖区分 Kocpy 接收、外部接管、已验证、副本达标和待处理。只有设置了明确的预计素材卷总数时，覆盖百分比才代表相对于计划的进度；中途接管项目时不要把未知历史量当成零。

“素材卷明细”使用四列显示日期与设备/机位、素材卷名称、文件与容量、接管可信状态。各列固定对齐，并按唯一逻辑素材卷统计。出现未处理清单差异的素材卷不计入收工达标；点击红色状态可查看全部差异并进入处理流程。

### 删除项目内部记录并重新测试

需要清空 Kocpy 对某个项目的认识并重新执行接管、备份和归档全流程时：

1. 先确认项目没有等待、复制、暂停、校验中的备份任务，也没有未结束的代理任务。
2. 在“进行中”或“已归档”页签找到项目，打开项目卡片右上角的更多菜单。
3. 选择“删除项目记录”，核对预览中的任务、代理、健康记录、归档变化和提醒数量。
4. 勾选风险确认，并准确输入完整项目名称；两项都满足后才能执行删除。

此操作会永久清理 Kocpy 内部的项目配置、关联备份任务与文件索引、关联代理队列记录、归档健康记录、变化记录和提醒。它不会删除或修改素材源、目的地备份目录、PDF/JSON/CSV 报告、MHL/ASC MHL、项目归档包或冷归档文件。删除后可以使用相同磁盘目录重新创建或接管项目；旧导出文件仍由用户自行保管。

进行中项目不再需要为了删除而先归档，但安全条件没有降低：只要存在等待、复制、暂停、校验中的备份任务，或未结束的代理任务，主进程都会拒绝删除。项目状态不会绕过这一检查。

### 自定义项目模板

“归档维护 → 项目模板与交接”提供五个带说明的系统模板：广告、纪录片、短片、综艺和电影。它们的设备组合、物理副本数、检查表和完成动作不同，模板卡片会直接显示这些差异。

- 系统模板不可直接改写，避免升级后默认规则含义漂移；可复制为自定义模板后重命名和编辑，也可隐藏并随时恢复。
- 自定义模板可设置名称、制作类型、用途说明、最多 10 个设备、每台设备的素材卷前缀与机位、1–4 份物理独立副本、预计素材卷、目录命名规则、完成动作、开工/收工检查表和制作人员。
- 项目卡片的“保存为模板”会以当前项目为草稿打开编辑器，不会直接静默保存。
- 应用模板前会显示“当前值 → 应用后”的逐项预览，可只勾选需要覆盖的配置。项目名称、拍摄日期和目的地磁盘路径永远不会由模板覆盖。
- 模板要求的副本数超过项目已配置目的地数量时，应用会被拒绝，需先补充目的地或取消该项覆盖。
- 自定义模板可导出为 JSON 并在另一台 Kocpy 工作站导入；导入文件受数量、大小、设备数量和命名规则校验。

## 7. 素材库与重新定位

素材库中的 Finder、播放和媒体信息是独立操作。若磁盘改名、备份目录移动或重新挂载后旧路径失效，使用“重新定位”选择新的副本根目录。Kocpy 先完整读取全部文件，再用原位置、新位置、文件数和操作类型请求确认；确认后会再次完整计算哈希，期间任何变化都会停止且不更新记录。若已有副本全部在线，同一入口会把所选目录作为另一份健康副本关联；若路径已记录则拒绝重复添加。原路径、目标路径、哈希证据和卷 UUID 会进入追加式审计，同盘目录仍不会增加物理独立副本数。

历史任务显示的绿色状态代表任务完成时的验证结果。几个月或几年后的当前健康状态，应通过“归档维护”重新校验。

## 8. 代理与交付

代理队列支持 H.264 与 ProRes Proxy、预设管理、自定义分辨率/码率/封装/命名、暂停继续、依赖、失败重试和批量导出。代理文件写入独立目录，不修改原素材。

可导出 Resolve CSV、Premiere CSV、Final Cut XML、完整 JSON，以及项目 PDF、CSV、MHL、ASC MHL 和带 `SHA256SUMS.txt` 的项目归档包。

MHL/ASC MHL 只允许从已完成、完整校验且没有未解决外部清单差异的副本导出。若重名处理改变了目的地文件名，导出清单使用已校验副本的真实最终路径。项目归档包若仍有未达副本要求的素材卷会拒绝生成，避免把不完整项目包装成安全归档。

## 9. 诊断与长期归档

诊断中心可以执行受控的 64 MiB 写入/回读性能预检，以及 64 MiB + 1000 小文件的有限读写测试，测试文件会先同步落盘再回读，结束后自动清理。脱敏诊断包会哈希化任务名、卷名、标签和路径，不包含素材内容、完整私人路径或账号信息。

归档维护支持整盘、项目、拍摄日、素材卷和单文件复校验；记录速度、风险、位置变化和未登记修改。修复损坏副本前必须存在一份再次哈希匹配的健康副本，并确认目标卷身份；原损坏文件会保留，修复后自动执行整任务复校验。

冷归档采用“写入临时文件 → 同步落盘 → 重新解压并校验完整性 → 原子发布”的顺序。只有以上步骤全部成功，热索引中的项目任务才会移除；恢复时同样限制文件大小、校验完整性并验证任务路径结构。

## 10. 数据、隐私与安装

### 窗口尺寸与滚动

- Kocpy 首次打开时读取当前显示器的可用工作区域，默认窗口不会超出屏幕。
- 标准最小窗口为 1080 × 720；若显示器工作区域更小，则以实际工作区域作为安全下限。
- 高度不足时左侧文字、图标、品牌和按钮保持正常比例；只有中间导航区域独立滚动，不再通过缩小字体或图标来挤入窗口。
- 模块按使用流程排列：工作台 → 拍摄项目 → 传输队列 → 恢复中心 → 素材库 → 代理队列 → 报告中心 → 存储设备 → 归档维护 → 诊断中心 → 使用说明。
- 长页面在主内容区纵向滚动，大型项目表格在窄窗口中横向滚动；弹窗内容在弹窗内部滚动，标题与底部操作不会被窗口裁掉。

Kocpy 不要求账号，不默认上传素材。应用数据保存在：

```text
~/Library/Application Support/Kocpy/
```

当前公开 DMG 尚未使用 Apple Developer ID 签名和公证。请只从 [Kocpy GitHub Releases](https://github.com/sexyfeifan/Kocpy/releases) 下载。如果 macOS 明确提示应用“已损坏”，确认来源后可执行：

```bash
xattr -dr com.apple.quarantine "/Applications/Kocpy.app"
```

不要全局关闭 Gatekeeper。

## 11. 遇到问题时先检查

1. 来源和目标磁盘是否仍然挂载，卷身份是否与原记录一致。
2. 项目目录是否符合“日期 → 设备/机位 → 素材卷”的规则。
3. 项目矩阵中的空白单元是否仍是“待确认”，而不是已经标记“当天未使用”。
4. 接管记录是否需要在项目详情执行一次“刷新接管信息”。
5. 新增目录是否从未接管；若是，应重新使用“接管既有备份”，而不是只刷新。
6. 仍无法判断时，到诊断中心导出脱敏诊断包。


## 12. 0.1.18 操作细节

### 先选范围，再执行

- 分级复校验必须明确选择项目、拍摄日、素材卷、文件或磁盘。单卷未选素材卷、单文件未填有效相对路径时，前后端均拒绝执行，不会退回整个项目。
- 改变项目会清空旧的素材卷和文件选择；磁盘模式只校验该目录内已有记录的副本，不把“已记录范围通过”说成整盘所有文件都安全。
- 接管范围或日期改变后会重新扫描预览。候选卷完整显示，可滚动核对；按钮区分“仅导入结构”“建立基线”“按外部清单校验”。
- 批量备份保留每项创建、启动状态。中途失败后使用“重试未提交任务”，不会重复创建已经返回任务 ID 的条目；已经运行的任务仍可在传输列表查看。批次提交后参数锁定，关闭并不删除已经创建的任务。

### 项目、模板、检查表

- 项目和模板允许每设备最多 5 个安全自定义机位名称，用中英文逗号分隔；输入逗号时不会被立刻吞掉，保存时去空格和重复项。目录分隔符和相对路径名称被拒绝。
- 自定义目录规则由预览和实际写入共用解析器。预创建只建立素材卷层之前的目录，不虚构素材卷。
- 在“检查表、提醒与变化审计”选择实际拍摄日、阶段、签署人，逐项勾选。必填项不齐不能签署；收工还必须处理当日未达标素材与未确认设备使用状态。
- 交接填写实际操作人；保存失败保留原输入。项目卡片提供“模板与交接”入口。
- 删除模板、NAS 预设需再次确认，仅移除配置，不删除素材。

### 后台操作与结果

- 接管、清单校验/修订、归档复校验/修复、冷归档、诊断等登记到“后台操作”中。关闭详情或切换页面可继续查看操作记录，不会将读取 100% 等同于校验成功。
- 维护期间阻止冲突传输与退出；提交阶段没有强制取消按钮。请等待安全结束，不要强制退出。意外中断的操作在重启后显示“结果尚未确认”，应从原入口重新核查。
- 原生文件选择器取消后不报成功；失败和详细结果保留在操作消息中。归档复校验显示健康数和问题数，而非一律“全部通过”。
- 修复归档副本前显示卷、目标路径、记录身份、候选健康来源和文件范围。来源逐文件重新哈希，原损坏文件另名保留。部分修复后失败会说明已完成数量，并保留未达标状态和审计记录。
- 冷归档先显示将卸载的任务/文件记录范围；归档包写入并校验成功后才卸载热记录，真实素材不删除。
- “刷新记录”不是重新哈希。要证明当前磁盘内容健康，应运行复校验。
- 任务完成使用非阻断提示，不会盖住正在编辑的表单。
- 复校验不重复执行首次传输的完成后动作，不会因此再次生成代理或自动推出设备。

### 素材、代理、报告

- 素材库每页最多 100 条，搜索防抖；不因每次传输字节更新重新查询。区分加载、失败、无结果，失败可重试。
- 默认从可访问的已校验副本打开素材；显示历史校验数和当前可访问数。可访问只表示路径存在，不代表已经重新校验。磁盘路径变化时仍需重新定位并验证哈希。
- 切换筛选/搜索或重建路径信息会清空旧的批量选择；可以主动清除选择。
- 代理加入队列不代表生成完成。暂停任务可以继续或取消，条目显示源、输出路径和依赖。
- 交付导出可限定来源素材卷，仅使用已完成代理；报告可选择历史拍摄日与项目。
- 批量推出先展示可推出盘和保留原因，确认后再次检查，结果逐盘列出。

### 提醒、NAS、局域网

- 复校验提醒可查看下一日期、修改天数、停用/启用和删除。
- NAS 预设可编辑名称、路径，新建备份时可直接选作目的地；须先通过 Finder 挂载网络盘。写入检查需确认，不对标识为素材源的介质提供普通写入测试。
- 局域网索引启动后，另一台工作站在“查看另一台工作站”填写显示的内网地址和访问令牌，点击读取。只展示项目与任务元数据，不合并记录、不复制素材。
- 令牌默认隐藏，不进入 URL 或持久化设置。共享项目输出不包含备份路径、制作人员或交接备注；请仅在受信任网络使用，结束后停止共享。

### 帮助、设置和窗口

- 默认帮助保持折叠；搜索帮助或点击“本页使用说明”可以直接找到模块。
- 备份完成不自动打开说明页；差异与基线弹窗提供就地概念说明。
- 主题属于设置草稿；未保存切页时恢复已保存主题。保存失败保留当前草稿。
- 侧栏文字与图标固定比例，低高度滚动导航；宽表格、长路径允许换行或滚动。Tab/Escape 作用于最上层弹窗，编辑表单关闭前提醒未提交内容。
