# Kocpy 0.1.13

0.1.13 让“缺失文件与额外文件同时存在”的外部清单差异可以按符合直觉的顺序完成处理。成功补回的文件不会再因为仍有额外文件而显示成远程调用错误；Kocpy 会保留修复结果、刷新弹窗并引导继续处理。此版本仍未使用 Apple Developer ID 签名与公证。

## 混合清单差异

- 同时存在缺失、额外、大小不同或校验不同项目时，弹窗明确显示“先补回缺失 → 自动完整核对 → 处理剩余额外文件”的顺序。
- 缺失文件安全补回后，即使清单仍未完全通过，也会显示“已补回 N 个文件；仍需处理……”的正常结果，而不是 Electron 远程调用错误。
- 重新核对后的素材卷文件记录、容量、状态和差异会完整刷新，后续建立基线不会继续使用修复前的旧文件集合。
- 手工移出误放文件后，可直接点击“重新完整核对”；Kocpy 不会自动删除、移动或重命名素材。

## 同名冲突与 0 字节文件

- 当清单缺少的路径带 `(1)` 等常见重名后缀，同时目录中存在名称相近的额外文件时，显示“疑似同名冲突”。
- 分别显示清单路径、预期大小、当前额外路径和实际大小；仅名称相似不会被自动视为同一文件。
- 额外文件为 0 字节时单独警告：空文件不能替代清单中的有效素材，建议先在 Finder 中隔离检查。
- 该识别只提供解释和处理建议，不降低 MHL/SHA 清单的路径、大小或哈希要求。

## 额外文件确认

- 纯额外差异可在当前弹窗直接执行“建立当前完整哈希基线”，无需退出后到项目列表另行操作。
- 基线建立过程逐文件读取当前素材卷并显示文件、字节、速度和剩余时间。
- 只有完整基线建立成功且用户明确勾选确认后，才能采用额外文件；原外部清单差异和确认记录继续保留用于审计。

## 真实问题核对

对 `20260828 / POCKET / Pocket4` 进行了只读核对：

- 外部 MHL 记录 `DJI_20260827201854_0001_D(1).LRF`，大小为 83,918,050 字节。
- 当前 DiskRAID 素材卷只有同目录的 `DJI_20260827201854_0001_D.LRF`，大小为 0 字节，不能替代清单文件。
- `m2_4T` 健康副本保留了 MHL 所需的 83,918,050 字节文件；其 SHA-256 与前一拍摄日保存的对应 LRF 完全一致。
- 因此原提示属于真实漏文件与额外空文件并存，不是 Kocpy 误判；0.1.13 改善的是解释与连续处理流程，不会把差异强行标绿。
