# 项目备份流程审阅

审阅日期：2026-10-16。范围：0.1.49 的项目备份路径与拍摄日链路，以及 0.1.50 源码修正。本文不是硬件认证或“不存在任何缺陷”的保证；候选功能的安装包公开和实际验收状态见[验证记录](VERIFICATION.md)。

## 核心结论

项目日、自然日期和操作时刻必须分开。现有结构可以表达大夜、补录、临时设备、整卡与按日分配，不需要移动真实素材或重写整套架构。但此次确实发现了目录权威与日期消费者的一致性遗漏，已纳入候选修正，不能把“主页面显示正确”当成整个流程一致的证据。

临时设备的原设计不是“只可加自然今天”，而是“只影响用户选定的拍摄日”。可以补录非今天的项目日；另一天真正使用同设备时须明确加入另一天，不能因为跨零点就自动扩大计划。

**后续增补复审发现发布阻断项**：整卡失败后同卷子目录成功被误当作覆盖原失败范围、归档包 MHL 短 ID 命名碰撞，以及混合日期项目报告逐文件归属不一致。2026-10-18 已加入候选代码修正和反例回归，仍需按最终门槛验证，不把下表既有修正或单项回归通过视为全链安全结论。触发、证据边界及发布状态见[验证记录](VERIFICATION.md)。

## 后续候选链路复核（2026-10-18）

- 确认输入与授权：不接受前端伪造筛选计划，创建/启动保持源与项目绑定、独立副本门槛及幂等请求；只补任务登记和进度合并，不改变写入权限。
- 执行与恢复：保留复制前后完整源及历史依据复核；新增遥测独立于复制/回读字节，不作为可信证据。失败、取消、暂停及旧任务保留原范围。实际隔离界面已走项目筛选和普通筛选、暂停继续、复校验；原始源哈希和文件身份另行核对不变。
- 统计与报告：沿用范围内统计和跨日贡献；项目文件明细改用同一确认投影，未知不补成任务日，CSV 明确任务摘要语义。单任务首次报告不改写；新生成的跨日项目 PDF 已检查文件归属和排版。
- 完成动作与推出：冻结副本要求共用；全部源根检查，同卷/同名不能替代范围证据，权限未知保留风险；普通 OS 卸载与合格推出分开，不授权格式化。
- 归档与交付：归档产物用完整标识、独占写入和完成标记。原 MHL/ASC MHL、任务 JSON 及按日媒体投影不重写历史；工作站交换沿用原冻结选择/日期证据，不宣称自动 `.kocpyproject` 或双机硬件验收。
- 位置与生命周期：副本重关联只迁移充分证明为同一文件的未完成代理输入，保留审计；项目删除提示交付恢复记录会被移除，独立 NAS 记录继续保留。私有规划、真实素材和生产记录不用于测试。

## 写入路径的权威与占用门槛

- 新项目任务必须带回用户刚刚核对过的项目名称、开始日、项目根目录名和命名规则。主进程将这四项与当前已保存项目逐项比较；任一缺失或变化都会停止创建，提示重新选择项目并核对路径。通过后才以后台权威字段生成任务，避免设置变化后仍按旧预览写入。
- 拍摄日严格校验真实日历日期，建议使用 `YYYYMMDD` 或 `YYYY-MM-DD`。例如 `2026-02-30` 不会被 JavaScript 自动滚到三月。旧工作区里已经存在的错误日期不会被过滤、改写或滚日；它仍显示为待修风险，缺失的旧项目根只做稳定、可识别的兼容回补。
- 同一项目中，不同设备在同一分钟领取卷名时使用项目级预留序号。预览与后台实际领取共享同一计算规则；同一分钟已有任一设备完成预留后，下一个设备会使用递增序号，即使两者卷名前缀不同。已有时间戳前缀约定不变。
- 新项目任务在进入任务记录前，会用各任务的冻结逻辑路径和已记录 `resolvedPath` 检查素材卷根。不同项目、普通任务或镜像任务只要这些已知根相同，或一方是另一方的祖先／子目录，就拒绝新任务；不同目的地上的同名相对目录仍可使用。这里不会遍历并解析全部离线历史目录，因此没有记录真实路径的旧符号链接别名仍须由操作人核对。
- 真正开始写入时，每个任务只异步解析自己的最多四个候选根，不同步遍历或唤醒全部历史 NAS。所有写入任务都会临时占用实际规范路径，阻止活动任务经符号链接、大小写或 Unicode 别名同时写入同一范围。新项目首次写入还会与历史逻辑根和已记录真实根复核；普通镜像的合法串行复用、同一任务重试和恢复不因历史记录本身被阻断。
- 目的地卷身份检查后、首次创建目录前，会再次确认实际路径仍等于预留路径；创建后再复查一次，再核对可用空间后进入媒体写入。权限错误或无法解析不会被猜测为安全。取消、失败和结束都会释放临时占用；暂停期间继续保留，避免另一任务趁暂停进入同一目录。

这些门槛不迁移旧任务、不改已有素材路径，也不删除目的地上无法归属的既有目录。若目的地已经有内容却没有任何 Kocpy 任务证据，仍应由操作人先核对来源，而不是由软件自动合并。

## 历史接管刷新与 NAS 范围

- 刷新既有接管记录时，只使用该任务绑定且校验通过的规则快照解释目录；快照缺失、损坏或重复时不会回退到项目当前规则。刷新可以重新观察当前文件数量，但保留任务原有日期、设备、机位、卷名、清单基线、哈希、首次报告和原 MHL，不把今天的项目设置改写成过去的接管事实。
- 同源或内容相同但历史归属、规则快照或逐文件日期分配不同的记录不自动合并。真正同归属的重复记录仍可按既有整理规则处理；无法证明的映射继续留作待确认。
- 独立归档转存／NAS 报告以用户实际选择的源目录为范围。选择路径精确对应已保存项目根时可以采用项目名称，但这本身不证明项目完整；选择拍摄日、设备、素材卷或普通子目录时使用所选目录名称。报告日期和历史只来自落在该源范围内任务的已记录归属；没有关联任务时不以项目计划周期推算日期，也不宣称整个项目已经转存完整。

## 路径实例与三种日期

默认例子：`/Volumes/BACKUP/20261015_示例项目/20261015/FX3/A/CARD_202610160230`。

- 项目根 `20261015_示例项目`：按项目开始日命名。
- 内层 `20261015`：操作人选择的拍摄归属日。
- `FX3/A`：该拍摄日的设备与机位；不分机位时无此机位层。
- 卷名 `CARD_202610160230`：实际领卷时刻，可以在次日凌晨；内容校验与报告记录真实操作时间，不回拨。
- 文件自己的时间仍是原始线索，不被改写来迎合目录；源日期线索也不自动成为已确认拍摄日。

自定义目录以开始前实际最终预览为准。规则变化不移动既有备份；不应在已打开向导时忽略配置变化继续开始。0.1.49 用户在期间修改过目录规则时，应先关闭并重新打开向导、重新核对路径。

## 不能由软件自动证明的事

- 跨午夜究竟是同一夜戏，还是下一场拍摄；设备时钟、时区或错误的 UTC 标记不能代替操作人确认。
- 未知附属文件该属于哪一天，或是否可删除；保守保留不等于自动正确分类。
- 某日未发现文件夹是否真的未使用；没有人工决定时继续待确认。
- 一个通过回读的目录是否与另一目录位于独立故障域；未知 RAID／NAS、分区或同盘多目录不能自动提升副本数。
- 按日派生产物或部分范围是否足以清卡；不完整覆盖始终保留边界。
- 既有备份中的非当日素材是否可以删除；本轮未提供这种删除，也不改写旧 MHL 或首次完成报告。

### 漏项必须有处理结论

每一项记录：编号、环节、类型、证据与复现、影响、是否必须补、是否阻止发布、关闭标准和当前状态。

- **已复现缺陷**：有实际错误与触发条件，需要修正并回归；涉及源改写、误覆盖、虚假校验／整卡结论、证据丢失或核心流程无法完成时，阻止受影响版本发布。
- **验证／覆盖缺口**：不等于已经有 bug。补相应验证；关键界面或准确安装包门槛缺失时不能发布，对真实硬件尚未验证的能力不能作认证承诺。
- **明确产品边界**：例如软件无法证明未知 NAS 的内部故障域，或无法单凭时间决定凌晨素材属于哪场拍摄。保留人工确认和真实提示，不以自动猜测“补齐”。
- **一般交互改进／可选功能**：评估收益、风险及替代方式；可延期，但需说明原因和安全操作路径，不为追求清单清零扩展未经授权的新功能。
