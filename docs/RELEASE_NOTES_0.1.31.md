# Kocpy 0.1.31

有限团队协作、默认保留本机冲突与可恢复审计版本。

- 每台安装建立跨重启稳定的随机工作站 ID；主机名称变化不改变身份，身份主／备份同时损坏时停止团队交换。
- 工作站配置包升级到 schema 3，记录来源工作站、唯一导出 ID、导出时间、应用版本、权威修订／摘要、交换范围摘要和项目／任务删除墓碑；整体 SHA-256 覆盖完整内容。
- 导入分为“选择并只读预检”和“确认后提交”。预检区分新增、精确重复、同内容不同任务 ID、同 ID 内容冲突、同名素材卷、项目字段、追加证据、模板／归档证据和删除冲突。
- 冲突一律默认保留本机，只允许逐项采用外部值，不提供批量覆盖。提交必须填写操作人、确认只处理元数据并通过系统确认；外部删除不会删除任何素材文件。
- 提交前重新读取配置包，并核对包 SHA-256、本机工作区修订／摘要及包含模板的交换摘要。预检后文件或本机状态变化会停止提交；包内模板经过严格结构、路径字段和数量限制检查。
- 合并按恢复日志、模板暂存、权威工作区提交和追加式审计的顺序发布。权威提交前失败会回退；提交后审计中断可在重启时完成，且不会重复合并。
- 审计保存来源、导出 ID、包摘要、操作人、预检依据、全部冲突决定、决定摘要、导入修订／摘要和结果。相同包加相同决定重复执行只返回原审计结果。
- 已接受的远端删除会同时从当前内存任务集合移除，避免下一次保存把旧记录重新写回。工作站包只交换 Kocpy 元数据，不复制、移动、删除或重新校验素材。
- “归档维护”显示本机稳定身份；合并审计默认折叠，展开后可核对来源、操作人、采用外部／保留本机数量、修订和包 SHA-256。软件内使用说明仍只在用户点击后打开，各模块默认折叠。
- 原有局域网索引保持临时令牌、只读、无原始路径与私人交接内容；本版不增加局域网写入、云同步或原始素材上传。

## 候选状态与发布门槛

当前仓库代码进入 0.1.31 候选阶段。自动化和单机隔离 A／B 数据目录验证不能代替真实团队环境；正式标签和公开 Release 必须等待至少两台真实 Mac 完成 A→B、B→A、冲突、重复导入、删除墓碑与重启后的双向核对。门槛未关闭前，GitHub Releases 的 latest 仍以已经公开验收的版本为准。

本版本仍无 Developer ID 签名／公证。团队交换不能证明另一工作站记录中的素材当前在线、完整或达到物理独立副本要求；备份与归档可信状态仍由原始哈希、逐目标独立回读、磁盘证据和复校验决定。
