# Kocpy 0.1.50

状态：源码候选，最终回归、实际界面及准确安装包验收尚待完成，未公开本版安装包。正式附件与公开状态以[同版 Release](https://github.com/sexyfeifan/Kocpy/releases/tag/v0.1.50)为准；不覆盖 0.1.49 或其他历史标签、安装包。

## 拍摄日不是自然今天

- 临时设备原本就可加入选定项目日，本版统一称“拍摄归属日／拍摄日临时设备”，明确支持过去和未来的已配置拍摄日，不仅限于今天。
- 新建备份与设备表单使用一致的合法日期集合，包括已有历史任务日。指定日入口保留上下文；通用入口优先恢复有效的上次向导选择，再提供自然今天或项目起始日作为预选。
- 大夜跨零点不自动切日。文件日期线索、拍摄归属日、实际备份时间与项目根开始日期分别保留；设备只属于明确加入的拍摄日，不扩散到其他日期、不提前建空目录。

## 大夜的显式归属调整

- 日期分析增加默认折叠的“批量调整拍摄归属日”：选择某个当前归属日期，再指定目标拍摄日，检查后应用到可调整的素材组草稿。
- 不自动取消任何日期勾选；必须保留、未知／共享内容与不可拆素材组不被批量强制分日。确认人和最终范围确认仍为必要步骤；部分范围仍不能作为完整卡或清卡依据。
- 不修改源文件、原时间、原 MHL 或旧任务目录；跨零点本身不构成排除素材的依据。

## 项目路径与日期证据一致性

- 新建项目任务在创建前对照后台已保存项目，核对名称、开始日期、项目根与命名规则；界面确认后若配置变化则拒绝并引导重新核对，不静默改用新路径，也不把旧路径绑定为新规则。
- 实际日历日期严格校验；错误日期不再通过日历滚动变成另一个日期。历史无效日期保留为可见、可修风险，不自动改写、滚日或隐藏旧记录；缺失的旧项目根以稳定兼容值回补，不改变原记录日期。
- 同一项目中，不同设备在同一分钟领取卷名时改用项目级预留序号。预览和后台实际领取共享规则；同一分钟已有任一设备完成预留后，下一个设备使用递增序号，即使卷名前缀不同。
- 新项目任务会用所有已记录任务的冻结逻辑根和已有 `resolvedPath` 检查绝对素材卷根；同根或祖先／子目录重叠均停止，大小写和 Unicode 组合采用保守比较。不同目的地下的同名相对路径不受影响。系统不会为此遍历全部离线历史 NAS，因此未记录真实路径的旧符号链接别名不在这项历史检查的证明范围内。
- 执行阶段只异步解析当前任务的最多四个目标，不同步遍历全部历史 NAS。所有正在写入的普通、镜像、项目、重试和恢复任务都保留活动路径占用；新项目首次写入另与历史逻辑根及已记录真实根比较。目的地身份检查后、首次建目录前及建目录后都会确认路径仍与预留目录一致，失败、取消或完成后才释放；暂停时继续占用。
- 按日归档、收工安全补充检查和日交接都识别人工确认后的日期贡献，不只看任务最初日期。归档保守校验相关任务的整个已记录范围，并明确可能包含其他拍摄日，不冒充仅检查该日文件。
- Resolve 按日媒体清单按文件确认归属导出；他日已确认视频不混入，仍未确认的视频保留、日期留空，增加归属状态与所选报告日列。
- 日摘要的默认“今天”使用本地日期；这只影响当前／未来提示，不改变拍摄事实或文件时间。

## 接管刷新与独立归档转存

- 刷新既有接管记录时，使用任务绑定且校验通过的规则快照，不再在快照缺失或损坏时套用项目当前规则。日期、设备、机位、卷名、校验基线、哈希、首次报告和原 MHL 保持原样；重新扫描的数量只作为当前观察值。
- 同源或同内容但历史归属、规则快照、逐文件日期分配不同的记录不会自动合并。无法证明一致时保留待确认，不以刷新制造完整结论。
- 独立归档转存／NAS 报告现在以实际选择的源目录作为上下文边界。精确选择已保存项目根时可以显示项目名称，但不据此证明项目完整；选择子目录时使用该目录名。日期和历史只取自该源范围内关联任务的已记录归属，没有关联任务时不按项目计划周期推算，也不把部分转存报告成完整项目。
