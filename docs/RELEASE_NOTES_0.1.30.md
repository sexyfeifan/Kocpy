# Kocpy 0.1.30

安全自动化、可解释建议与幂等完成动作版本。

- 素材源历史建议现在显示真实依据。相对路径与字节数完全一致只标为“疑似重复”，明确说明尚未重新读取内容哈希；卷身份历史与结构重复是两类独立证据。建议必须由用户点击应用，且只填写当前草稿，永远不会自动开始备份。
- 项目与模板中的完成动作改为“完成后建议”。任务完成只冻结规则快照下的建议计划，不会后台生成报告、写交付清单、加入代理队列或推出源盘。
- 每项完成动作需要填写实际操作人，并通过独立确认后执行。任务记录保存稳定幂等键、规则快照、授权时间、尝试、状态、产物摘要、结果与错误；重复完成事件或重复点击不会重复执行已完成动作。
- 报告和交付清单先保存计划路径与 SHA-256，再以不覆盖方式发布。中断后只有现存产物与计划摘要一致时才补记完成；路径冲突或摘要变化会停止，不会替换已有文件。
- 自动化代理任务带稳定来源键；中断重试或重复触发只补齐尚未入队的项目。源文件仍须来自已校验副本，并在实际转码前按 0.1.28 证据规则完整重读。
- 安全推出始终是一次性的用户授权。执行时重新核对任务清单／校验状态、当前源盘身份、活动备份和代理占用；离线或失败会保留具体原因，不会静默算作成功。
- 完成动作执行后，任务详情无论成功、跳过或失败都会重新读取审计状态；失败原因、重试入口和尝试次数无需关闭详情后再打开。
- 外部 MHL／SHA 清单修订、差异接受、首次基线、素材删除和副本标准降低不属于完成动作，不能由本版自动化触发。

## 升级与限制

旧项目和模板的 `completionActions` 配置继续读取，但从本版本起只产生待确认建议，不再被解释为对未来每次外部副作用的永久授权。升级不会自动执行历史任务的动作；打开已完成任务详情时可建立兼容建议并由用户逐项处理。

本版本仍无 Developer ID 签名／公证。自动测试和桌面验收只使用仓库外隔离合成数据；真实 NAS、拔盘、断电、睡眠、空间耗尽及全部文件系统矩阵未因此宣称完成。最终发行附件、架构、测试结论与 SHA-256 以 [验证记录](VERIFICATION.md) 和 GitHub Release 实际附件为准。

完成动作的授权与执行记录在 0.1.30 中属于当前工作站的本地审计记录；跨工作站交换、稳定来源标识与冲突合并属于 0.1.31 的独立验收范围。本版不会把另一台工作站缺失的完成动作记录自动解释为已执行，也不据此改变备份可信状态。
