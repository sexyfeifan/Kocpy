# Kocpy 0.1.14 安全与可靠性审计

审计日期：2026-08-30

范围：复制与校验、异常恢复、任务持久化、SQLite 索引、外部清单、归档修复、安全推出、诊断隐私、工作站导入、冷归档、报告可信度、窗口与使用说明、构建发布。

## 结论

本轮发现的高优先级代码问题已在 0.1.14 修复，当前没有已知会把未完成数据标成成功、把不同磁盘误当成原磁盘继续写入、或因单侧记录较旧而直接丢失任务的 P1/P2 缺陷。所有写入式自动测试只使用系统临时目录；没有读取或修改用户正式素材。

仍需外部条件才能完成的项目属于硬件/环境验收，不是代码待实现项：实体 exFAT/HFS+ 介质、真实 SMB/NFS 服务、拔盘与断电注入、Intel 实机、Developer ID 签名与 Apple 公证。正式片场上线前仍应以有其他健康副本的素材做一次对应环境试运行。

## 已修复问题

### 1. 复制完成与磁盘身份

- 修复慢速目标异步写入引用可变读取位置的问题；每个数据块使用固定偏移。
- 复制期间周期性核对源与目的地身份，完成前再次核对。
- UUID 已记录但当前 UUID 缺失时不再放行，避免挂载点回落到系统盘后误写。
- 完成前重新扫描全部文件和空目录；新增、删除、大小或修改时间变化都会失败。
- 发布文件执行文件同步和父目录同步，保留权限、访问时间、修改时间；空目录元数据也在完成前恢复。

### 2. 持久化与恢复

- JSON 主文件无效时不覆盖健康备份。
- SQLite 打开、备份恢复均执行完整性检查；无效任务/项目行不再静默忽略。
- 任务头与文件记录规范化分表，避免文件清单在 SQLite 内重复保存；旧版嵌入式文件记录仍可迁移。
- 目录文件增加顺序字段，重载后保持原文件顺序。
- 运行中使用 JSON 轻量检查点，结算时更新 SQLite，消除大型数据库每秒完整导出。
- 启动合并 JSON 和 SQLite 的记录并集，按最新检查点选择同 ID 任务；只有存在差异时重建索引。
- 退出同时等待两个持久化写入队列。

### 3. 工作站包与冷归档

- 新工作站包使用 schema 2 并强制完整性签名；兼容旧 schema 1。
- 导入检查绝对路径、相对路径越界、哈希算法、任务状态、目的地和文件副本结构；导入后同步重建索引。
- 备份/代理进行时拒绝导入、恢复冷归档和重建索引。
- 冷归档写入临时文件并落盘，重新解压和验证完整性后原子发布；只有成功发布才移除热记录。
- 冷归档恢复限制压缩输入和解压输出大小，并复用工作站任务结构验证。

### 4. 清单、报告与修复

- 外部清单拒绝重复路径、目录越界和混合哈希算法。
- MHL/ASC MHL 使用已校验目的地的真实最终路径，覆盖重名后缀场景。
- 未完成、无完整校验副本或清单差异未解决时拒绝导出可信 MHL。
- 项目归档包要求每个素材卷满足项目副本数和清单要求。
- 单任务、拍摄日和项目报告统一使用清单与物理副本判定，不再仅凭 `completed` 显示绿色。
- 修复归档副本前重新哈希健康副本并确认目标卷身份；唯一暂存文件落盘后发布，保留旧损坏文件并执行整任务复校验。
- 同一素材卷的基线、补回、重校验、接受额外项、修订 MHL 和归档修复使用主进程互斥锁，避免重复点击并发写入。

### 5. 安全推出与诊断隐私

- 自动完成动作推出素材源，不推出备份目的地。
- 子目录会先解析到真实可推出卷；批量推出前重新确认素材卡身份和当前清单。
- 可靠性验收在回读前同步大文件与每个小文件。
- 诊断包哈希化任务名、路径、卷名和目的地标签，仅保留排障需要的容量、状态、性能和匿名标识。

## 验证矩阵

- TypeScript 静态检查。
- 常规自动化测试：复制、断点、重名、符号链接、源变化、持久化恢复、SQLite 恢复、清单解析与修复、报告、代理、项目收工、窗口布局。
- 10 万与 100 万文件 SQLite 索引压力。
- Electron 生产构建与 npm 高危漏洞审计。
- Apple Silicon 与 Intel 双架构 DMG 构建、`hdiutil verify`、包内版本与 Mach-O 架构检查。
- Git 补丁空白与格式检查。
