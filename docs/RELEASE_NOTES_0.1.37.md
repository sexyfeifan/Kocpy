# Kocpy 0.1.37

本版把“完整接收”和“按日交付”明确拆开，并补齐项目日视图、自动报告、空目录治理与独立归档转存。所有新流程继续以只读素材源、逐目标回读和保守的副本计数为前提。

## 完整素材卡与混合拍摄日

- 项目详情现在按拍摄日分组。每个日期单独显示设备／机位、素材卷、文件、容量、“完整卡副本达标”与当日素材卷明细；当天或有风险的日期保持展开，未来未确认日期明确标为可折叠的计划日，只有没有风险和待确认项的日期才显示为安全。
- 同一张卡包含多个拍摄日时，首先完整备份并校验整张卡。Kocpy 不会为了按日整理而删除、移动或改写完整卡。
- 可从一个已校验的完整卡副本分析素材日期。媒体内嵌日期、路径日期和修改时间只提供建议；实际归属必须由操作人逐素材组确认并保存。
- 可从确认后的日期归属生成独立“当日交付副本”。交付再次进行 SHA-256 读取校验，并保存自己的 MHL／JSON 与 PDF 报告；中断后可继续，报告失败可单独重试。
- 当日交付是完整卡的派生产物，**不计作新的素材卡、备份任务或物理独立副本**，也不表示未选择的素材可以从完整卡删除。

## 当日交付的恢复与安全发布

- 可恢复交付在交付根目录保存隐藏的 `.kocpy-daily-delivery.journal.ndjson`。它位于 `Media` 之外，是 Kocpy 管理的恢复证据，不属于交付素材。日志事件以 SHA-256 前后链接；已完整落盘的事件被修改、缺失或与持久化游标不一致时会安全停止，不会猜测继续。
- 恢复同时绑定源卷、目标卷的完整身份，以及目标父目录、最终目录、`Media`、报告目录和逐层父目录的 `dev/ino`。无 UUID 的 NAS／挂载只有在已记录的挂载来源摘要、文件系统、挂载点和目录身份全部一致时才能恢复；同名重挂载只要身份变化就会停止。
- 安全文件读写使用 `O_NOFOLLOW` 并复核打开前后的 inode、链接数和时间信息；符号链接、额外硬链接或中途替换都会停止。成品只以排他方式不覆盖发布；文件系统不支持硬链接时，回退为 `O_CREAT | O_EXCL | O_NOFOLLOW` 的排他复制，不放宽安全边界。
- 复制完成后会对所有交付文件做一次终态全量 SHA-256，再发布 JSON／MHL；清单发布后还会重新核对 `Media` 目录的精确文件集、文件身份和清单摘要。PDF 报告发布后同样会回读 SHA-256，再按记录的报告清单重新授权和复核。
- 恢复日志的硬上限为 **128 MiB**。开始复制素材前会根据冻结清单估算日志上界；预计超限时在任何交付素材写入前停止，要求缩小单次范围。高延迟 NAS 上的关键边界同步落盘可能降低速度；当前没有真实 SMB／NAS 吞吐基准。
- 安全补丁前的 0.1.37 候选任务若缺少完整卷身份，记录仍可读，但不能安全续传或重写报告。Kocpy 会保留已有内容并停止；请重新预检并新建交付任务。

## 新任务的完整清单与自动 PDF

- 0.1.37 新建任务冻结 `complete-v2` 清单策略。默认把隐藏项、AppleDouble、已有 MHL／XML／PDF 和空目录纳入复制范围，目标按相同范围验证；符号链接或特殊文件会明确停止，不会静默漏过。
- 若用户主动关闭“包含隐藏文件”，每一项被排除的隐藏文件／目录、字节数和原因都会在任务范围中冻结并显示。它是明确的过滤任务，不会冒充未过滤的完整素材范围。
- 完全空的源目录、只有空目录的源也可以在新策略下被准确复制并验证。升级前创建、没有策略快照的旧任务继续使用历史扫描规则，恢复和重试不会被静默改写。
- 新任务默认开启“完成后自动生成 PDF”。可在设置改变新任务默认值，也可在开始前为单个任务关闭。任务及全部目的地完成校验后，每个备份目的地会在对应素材卷目录的 `Kocpy报告` 下保存一份报告，而不是写到磁盘根目录或项目根目录。
- 完整素材结论针对首次扫描冻结的范围：每个源项目都有记录的目标映射并完成内容、精确字节与空目录核对；冲突后缀模式可能改名，目的地既有额外项不会被删除或当成源内容。校验结束后生成的管理报告不属于源卡素材范围。自动 PDF 是“首次完成校验快照”，以后移动副本时保留原始报告字节和历史路径，不伪造为当前路径。
- 报告写入采用不覆盖发布并在落盘后重新读取、核对精确字节与 SHA-256。某个目的地报告失败不会改变已经完成的数据校验，可在报告中心只重试未完成的报告。

## 项目目录与收工整理

- 新项目默认按需创建目录：先保存日期、设备和机位计划，首次向对应单元备份时才建立实际目录，减少未使用设备造成的空文件夹。需要预先交付完整目录树时，仍可明确开启“保存时预建全部目录”。
- 旧项目没有新设置时保留原有预建行为，不自动迁移或删除既有文件夹。
- 确认“当天未使用”或“整日休息”后，Kocpy 先逐路径预览可能整理的空脚手架目录。只有当前工作站有 Kocpy 创建证明、执行时仍为空、磁盘身份一致、没有任务引用且不与其他日期／设备共享的真实目录才可被移除。
- 整理必须填写操作人并再次确认；未知目录、导入记录、符号链接、非空目录、共享自定义命名路径和不符合范围的目标一律保留。逐目标结果进入项目审计。

## 独立归档转存（NAS 或已挂载目录）

- 新增四步归档流程：选择或拖入源项目文件夹 → 选择 NAS、网络共享、外置盘或其他已挂载目录的父目录 → 核对文件、精确字节、空目录、文件系统、挂载点与实际最终路径 → 开始复制并独立回读。Kocpy 只确认目标是当前可访问的已挂载目录，不把任意目录冒充为已确认的 NAS。
- 最终目录保留源根文件夹名称，不覆盖同名目标，不删除本地源，也不增加素材卡或项目副本统计。该流程可关联项目名称和拍摄日期，也可直接处理普通文件夹。
- 支持把已校验备份盘带到另一台安装 Kocpy 的 Mac 再转存 NAS：即使第二台 Mac 没有原项目记录，也能独立扫描、复制、回读和生成报告；若先通过工作站配置包合并原项目记录，可再关联项目，补充报告元数据与历史证据。
- 0.1.37 新建的中断任务会保留独立恢复状态；恢复前重新核对源、目标与卷身份。复制成功后从目标目录逐文件读取 SHA-256，并核对相对路径、精确字节与空目录。
- 在最终归档的 `Kocpy报告` 内生成明细 PDF 和高清 PNG 摘要图，包含归档／项目名称、拍摄日期、文件数、数据量、源路径、实际归档路径、开始／完成时间和范围摘要。两份产物发布后都会重新读取并记录精确字节与 SHA-256；界面提供目录、PDF 与 PNG 独立入口。数据已校验但报告失败时显示双状态，可单独重试报告而不重新复制。
- 早期 0.1.37 候选保存的旧格式转存记录会先验证再迁移：已完成记录只读保留；未完成或正在生成报告的记录会安全终止，必须重新选择源与目标并预检，不能续传。迁移不补写旧版未采集证据，也不会把旧记录误记为完成。
- 该结论不自动判断目标是不是 NAS，也不验证服务器内部磁盘拓扑、磁盘占用、ACL、扩展属性、权限或创建／修改时间，不证明历史拍摄从未漏项；既有 MHL／PDF 作为 payload 原样复制，不会被自动解释或改写。
