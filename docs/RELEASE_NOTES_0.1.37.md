# Kocpy 0.1.37

本版把“完整接收”和“按日交付”明确拆开，并补齐项目日视图、自动报告、空目录治理与独立 NAS 归档转存。所有新流程继续以只读素材源、逐目标回读和保守的副本计数为前提。

## 完整素材卡与混合拍摄日

- 项目详情现在按拍摄日分组。每个日期单独显示设备／机位、素材卷、文件、容量、收工状态与当日素材卷明细；当天或有风险的日期保持展开，已安全日期可以折叠。
- 同一张卡包含多个拍摄日时，首先完整备份并校验整张卡。Kocpy 不会为了按日整理而删除、移动或改写完整卡。
- 可从一个已校验的完整卡副本分析素材日期。媒体内嵌日期、路径日期和修改时间只提供建议；实际归属必须由操作人逐素材组确认并保存。
- 可从确认后的日期归属生成独立“当日交付副本”。交付再次进行 SHA-256 读取校验，并保存自己的 MHL／JSON 与 PDF 报告；中断后可继续，报告失败可单独重试。
- 当日交付是完整卡的派生产物，**不计作新的素材卡、备份任务或物理独立副本**，也不表示未选择的素材可以从完整卡删除。

## 新任务的完整清单与自动 PDF

- 0.1.37 新建任务冻结 `complete-v2` 清单策略。默认把隐藏项、AppleDouble、已有 MHL／XML／PDF 和空目录纳入复制范围，目标按相同范围验证；符号链接或特殊文件会明确停止，不会静默漏过。
- 若用户主动关闭“包含隐藏文件”，每一项被排除的隐藏文件／目录、字节数和原因都会在任务范围中冻结并显示。它是明确的过滤任务，不会冒充 A=B 完整模式。
- 完全空的源目录、只有空目录的源也可以在新策略下被准确复制并验证。升级前创建、没有策略快照的旧任务继续使用历史扫描规则，恢复和重试不会被静默改写。
- 新任务默认开启“完成后自动生成 PDF”。可在设置改变新任务默认值，也可在开始前为单个任务关闭。每个实际已校验目的地都会在对应素材卷目录的 `Kocpy报告` 下保存一份报告，而不是写到磁盘根目录或项目根目录。
- 报告写入采用不覆盖发布并在落盘后核对 SHA-256。某个目的地报告失败不会改变已经完成的数据校验，可在报告中心只重试未完成的报告。

## 项目目录与收工整理

- 新项目默认按需创建目录：先保存日期、设备和机位计划，首次向对应单元备份时才建立实际目录，减少未使用设备造成的空文件夹。需要预先交付完整目录树时，仍可明确开启“保存时预建全部目录”。
- 旧项目没有新设置时保留原有预建行为，不自动迁移或删除既有文件夹。
- 确认“当天未使用”或“整日休息”后，Kocpy 先逐路径预览可能整理的空脚手架目录。只有当前工作站有 Kocpy 创建证明、执行时仍为空、磁盘身份一致、没有任务引用且不与其他日期／设备共享的真实目录才可被移除。
- 整理必须填写操作人并再次确认；未知目录、导入记录、符号链接、非空目录、共享自定义命名路径和不符合范围的目标一律保留。逐目标结果进入项目审计。

## 独立 NAS 归档转存

- 新增四步归档流程：选择或拖入源项目文件夹 → 选择已经在 Finder 挂载的 NAS 父目录 → 核对文件、精确字节、空目录与实际最终路径 → 开始复制并独立回读。
- 最终目录保留源根文件夹名称，不覆盖同名目标，不删除本地源，也不增加素材卡或项目副本统计。该流程可关联项目名称和拍摄日期，也可直接处理普通文件夹。
- 中断任务会保留独立恢复状态；恢复前重新核对源、目标与卷身份。复制成功后从 NAS 逐文件读取 SHA-256，并核对相对路径、精确字节与空目录。
- 在最终归档的 `Kocpy报告` 内生成明细 PDF 和高清 PNG 摘要图，包含归档／项目名称、拍摄日期、文件数、数据量、源路径、实际 NAS 路径、开始／完成时间和范围摘要。报告失败可单独重试，不重新复制已校验数据。
- 该结论不验证 NAS 服务器内部磁盘拓扑、磁盘占用、ACL、扩展属性、权限或创建／修改时间，也不证明历史拍摄从未漏项；既有 MHL／PDF 作为 payload 原样复制，不会被自动解释或改写。

## 验证与已知限制

完整清单、空目录、自动报告、混合日期分配、当日交付、目录整理和 NAS 转存均使用隔离合成数据进行自动回归；最终安装包的精确测试数量、架构与桌面验收证据以[验证记录](VERIFICATION.md)和同版 GitHub Release 为准。

当前仍**没有 Developer ID 签名或 Apple 公证**；ad-hoc 签名不等于 Apple 来源认证。自动测试、磁盘映像或同一物理盘上的多个目录不能代替真实现场介质。本版不宣称已经覆盖所有 NAS、真实双外置物理盘、网络中断／重挂载、拔盘、睡眠、空间耗尽、ACL／扩展属性或全部相机格式；投入生产前请用非生产数据和自己的存储链路验收。
