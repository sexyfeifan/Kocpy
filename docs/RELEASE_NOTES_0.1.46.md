# Kocpy 0.1.46

> 此候选因最终媒体完整摘要与来源记录不一致而保留草稿，未公开，也不用于安装或升级测试。标签及原附件保持不变；界面、扫描和媒体来源修复由后继 0.1.47 交付。

## 界面与真实进度

- 冷银玻璃面板、细边框、银色主操作和蓝／青／紫功能图标，深浅主题共同覆盖表单、焦点和任务状态。
- 工作台显示真实素材源与各目的地的进度，复制和独立回读分别呈现。内容已校验、范围完整与物理独立副本要求分别判断，不凭目标数量或绿色图标宣称达标。
- 保持原侧栏字号与图标尺寸；导航、主内容和弹窗正文独立滚动，长路径通过换行或滚动查看，关键操作保持可达。
- 延续现有新建备份向导、暂停／继续、任务详情和危险操作确认，状态与进度使用引擎提供的任务记录。

## 素材目录扫描

- 新任务在读取元数据或遍历前跳过 `.Spotlight-V100`、`.Trashes`、`.fseventsd`、`.TemporaryItems`、`.DocumentRevisions-V100`、`.PKInstallSandboxManager` 和 `.PKInstallSandboxManager-SystemSoftware` 系统目录。
- 子目录或条目出现 `EPERM`／`EACCES` 时记录排除证据并继续扫描其他素材。普通隐藏文件、AppleDouble 与 `.DS_Store` 仍遵循“包含隐藏文件”设置；素材源根目录不可读、其他读盘错误、符号链接和特殊文件仍明确停止。
- 扫描界面、任务范围与报告保留排除路径、原因、权限码及大小未知标记；ASC MHL 的 `ignore` 保存冻结范围中的精确排除路径。未遍历子树的容量与数量保持未知，不当作已读取的零字节或空目录。
- 权限排除只允许证明已纳入内容的校验结果，不能计作整卡完整副本或满足项目副本要求，也不能借“推出已完成素材卡”清除未读风险。
- 权限遗漏仍进入“需处理”筛选；完成横幅与系统通知使用同一范围结论，明确显示权限排除，避免普通成功文案掩盖未读取范围。
- 旧任务保留原冻结策略与路径；处理权限后保留旧记录并新建任务。源变化复扫、哈希、卷身份及逐目标独立回读要求继续生效。

## 安装、升级与验证边界

正式安装包、准确 SHA-256 和公开状态以[同版 GitHub Release](https://github.com/sexyfeifan/Kocpy/releases/tag/v0.1.46)为准，自动测试、架构、最终安装包与桌面验收证据见[验证记录](VERIFICATION.md)。草稿、源码提交和界面样张不代表已发布或完成验收。

已安装版本的“检查更新”在正式 Release 公开后打开匹配架构的 DMG 下载链接。核对同版 `SHA256SUMS.txt` 后，等待任务安全结束、导出本地数据备份、正常退出并手动替换“应用程序”中的 App，再启动确认版本与记录。具体步骤见[安装与升级](INSTALLATION.md)。

安装包采用 ad-hoc 签名，**没有 Developer ID 签名或 Apple 公证**。准确媒体对应源码、完整许可与构建来源随同版附件提供。原生 Apple Silicon、Rosetta 与原生 Intel 的结论分别记录；自动测试或虚拟卷结果不扩张为真实 NAS、物理双盘、拔盘或全部相机格式认证。
